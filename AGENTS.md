# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project

preenFM3 firmware for an STM32H753 (Cortex-M7, 480 MHz). C11 / C++11.
- `firmware/` — main synth firmware
- `preen_lib/` — shared display, input, board, storage library
- `bootloader/` — standalone bootloader
- `third_party/` — vendored HAL, CMSIS, FatFs, display, MSFA
- `hardware/` — PCB and mechanical files
- `doc/` — hardware, compilation and design notes

Default sound engine is **PFM3**. The DX7 (Dexed) engine is an additional
engine, opt-in per timbre.

## Build and flash

```sh
cmake --build build -j"$(nproc)"
st-flash --reset write build/firmware/p3_1_04.bin 0x08020000
```

- `./rebuild.sh` does a clean rebuild and prints the size of both ELFs.
- If flashing fails with `Failed to enter SWD mode`, simply retry.
- "build and flash" means run both commands without asking for confirmation.

## Verifying changes

- Trust only `cmake --build` output. The editor/LSP reports false errors
  because the ARM include paths are not configured: `stm32h7xx_hal.h` /
  `Common.h` not found, unknown `uint8_t`, `fatfs/integer.h` typedef
  redefinition, incomplete types. Ignore them.
- After a successful build, check the memory report; DTCMRAM and RAM_D1 are
  tight (both > 85% used).
- Flashing is the normal way to verify hardware-facing changes.

## Device state without a screenshot

`scripts/read_state.sh` decodes the live UI state from RAM over stlink. Run it
instead of a screenshot when you only need position/state (`--json`, `--raw`
also available).

To navigate the UI, use `doc/navigation_page_tree.md`: it maps every page,
button, state and encoder slot for DX7/PFM3/909, with quick button recipes. Drive
it with `scripts/navigationn_press_button.sh <1-12>` — no need to read the
editor code to find a page or reach a given state.

Typical output:

```
synthState @ 0x2000a18c  mode=Editor  timbre=1  editName=''
  mainPage=0  mixerColumn=Mix  menuSelect=0  currentMenuItem=0x080c2cbc
  engineEditor: editPage=4 pageState=1 pageStates=[0, 1, 0, 0, 1, 0, 1, 0]
  engines: t1=909/1v  t2=PFM3/16v ...
```

- `mode`: 1 Mixer, 2 Editor, 3 Menu, 4 Sequencer.
- `timbre`: selected instrument; `mainPage` is the selected main-page index
  (`-1` = none); `mixerColumn` is the Mixer column (Mix/Out/Inst/Midi/Scala/
  Global).
- `editName`: scratch buffer for name-entry menus (empty otherwise).
- `engineEditor`: the active engine editor's `editPage` and that page's
  `pageState`. Engine page state lives per editor in
  `EditorEngine::enginePageState_` (reached via `displayEditor.cachedEditor_`),
  **not** in `fullState.buttonState`. `editPage`/`pageState` are engine-specific
  indices.
- `buttonState`: non-zero `FullState::buttonState[]` entries (shared pages,
  mixer, menu, operator/matrix selectors), named from `Common.h`.
- `engines`: per-timbre engine + voice count from `mixerState_`.

Pitfalls:

- On a shared page (e.g. Arp/Fx) the engine editor's `editPage` is stale; the
  shared page state shows up in `buttonState` under `BUTTONID_EDIT_*`.
- Offsets are generated by a compile-time `offsetof` probe into
  `build/state_offsets.txt` (regenerated when relevant headers or the script
  change). Do not hardcode field offsets.
- `gdb`/`pahole` cannot read `SynthState`/`MixerState` (polymorphic DWARF), which
  is why the probe exists.

Primitives used: `arm-none-eabi-nm -S build/firmware/preenfm3_firmware.elf | grep
<symbol>` for addresses/sizes (`synthState`, `displayEditor`), and `st-flash
read <file> <addr> <size>` for non-destructive RAM reads. `scripts/pull_png.sh`
requires confirmation before pulling or analysing an image; use it only for
visual debugging.

## Working style

- When you are unsure whether something matters (for example a code-size
  increase, a compiler warning, or a possible performance regression), stop and
  ask the user. Do not spend a lot of time investigating unless they confirm it
  is worth investigating.
- If the user asks a question, do not change code. Answer the question and wait
  for an explicit "Go" before making any code change.

## Code conventions

- Prefer minimal, targeted changes. Do not refactor or over-engineer.
- Match the surrounding style; avoid adding comments unless they explain
  non-obvious hardware behaviour. Keep comments short and clear.
- No dynamic allocation in the audio path.
- The 16 global voices are shared by all engines; do not add a separate voice
  pool per engine.
- `TFTAction.actionType` is a plain `uint8_t` (not a bitfield).
- `TftAlgo.cpp` exists twice: `preen_lib/src/display/TftAlgo.cpp` (real) and
  `bootloader/src/TftAlgo.cpp` (dummy). Every new `TftAlgo` method needs a
  bootloader stub or the bootloader will fail to link.
- TFT big font is fixed-width: parameter/button names longer than ~7
  characters collide. Keep names short.

## DX7 engine (opt-in)

- Keep PFM3 as the default engine; DX7 is selected per timbre.
- Do not add DX7 parameters to `Pfm3Preset`.
- DX7 has no unison mode.
- DX7 program layout (156 bytes): operator block `(5 - operatorNumber) * 21`;
  rates at `[0..3]`, levels at `[4..7]`; global data from `[126]`; algorithm
  `[134]`; feedback `[135]`; operator on/off mask `[155]`.
- Only DX7 algorithms 4 and 6 have multi-operator feedback loops; all others
  are self-feedback.
- DX7 operators are all sine; only the global LFO has a waveform.
- The DX7 envelope display maps levels linearly and derives each stage
  duration from its rate only (see `getDx7EnvelopeDisplay()`).
- Vendored MSFA files stay Apache-2.0 and must keep their upstream headers.

## Git

- Never create commits. The user commits themselves; an explicit request
  does not change this.
- Never amend or force-push.
- Do not commit `build/`, binaries, or editor artefacts.
- Do not commit secrets or keys.

## Domain notes

- Sample rate is `PREENFM_FREQUENCY` = 47916 Hz (`Common.h`).
- USB uses **TinyUSB** (`third_party/tinyusb/`, code in
  `firmware/src/platform/usb/`). Firmware is a composite UAC2 capture + MIDI
  device; bootloader is USB mass storage. Audio is the sum of the three DAC
  buffers, resampled to 48 kHz, 16-bit stereo. See `doc/usb_audio.md` and
  `doc/tiny_usb_port.md`.
