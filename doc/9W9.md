# 9W9 — TR-909 drum engine for preenfm3

Notes on bringing the X0X 909 drum part to preenfm3 as a new `SynthEngine`.
This is the 909 only: no 808, no 303, no breaks, no X0X sequencer.

## What 9W9 is

**9W9** is a TR-909 emulation by [athousanddetails](https://github.com/athousanddetails/schwung-9W9).
It is itself grown out of **ER-99** by Matthew Cieplak. Both are GPL-3.0.

9W9 is a *circuit model*, not a sample pack: the bass drum, snare, toms, rim
and clap are synthesised from oscillators, envelopes, filters and diode
shaping. Only the hi-hat, ride and crash are samples (from ER-99).

X0X ([charlesvestal/fm1-x0x](https://github.com/charlesvestal/fm1-x0x)) is a
Felucca fork, but the drums are **not** Felucca engines and are **not** part of
the MIT `Felucca-Engines` repo. They are a separate DSP layer added by X0X:

| File | Content |
|------|---------|
| `firmware/src/dsp/drum909.c` | the 909 voices and the engine table |
| `firmware/src/dsp/drum909.h` | `drum909_t`, voice state, API |
| `firmware/src/dsp/drum909_dsp.h` | envelopes, biquads, oscillator, noise, tanh, distortion |
| `firmware/src/dsp/fastmath.h` | no-libm `exp`/`log2`/`sin`/`tanh` helpers |
| `firmware/src/dsp/x0x_param.h` | parameter descriptor used by the X0X UI |
| `tools/gen_drum_samples.py` | generates the mu-law samples and the lookup tables |
| `assets/909/{hh,ride,crash}.wav` | the sampled 909 metal sounds |

Generated at build time (not committed):

- `x0x_drum_samples.h` — the three samples as 8-bit mu-law (G.711) plus the
  256-entry decode table. About 110 KB, flash-resident.
- `x0x_drum_tables.h` — the `tanh` lookup and 9W9's EXP pot curves
  (`min * (max/min)^(pot/127)`), evaluated at generation time so the device

The upstream DSP and samples are 44.1 kHz. Keep the 909 running at 44.1 kHz and
resample its stereo output to `PREENFM_FREQUENCY` (47916 Hz) at the engine
boundary; the vendored DSP and `gen_drum_samples.py` stay unmodified at 44.1 kHz.

## How the 909 makes sound

All voices run at the sample rate, mono, float, no libm, no allocation. The
909 has **one voice per drum** (retriggering a drum restarts it); the kit is
mixed internally into a dry bus, with optional reverb/delay sends and per-voice
pan.

Shared building blocks (`drum909_dsp.h`):

- **Envelopes**: Web Audio `setValueAtTime` + `exponentialRampToValueAtTime`
  emulated as a per-sample recursive multiplier, re-anchored to the closed form
  once per block.
- **Filters**: RBJ biquads (LP/HP/BP), direct form 1.
- **Oscillators**: triangle on a `uint32` phase (`2^32` = one cycle).
- **Noise**: xorshift32, uniform `[-1, 1)`, shared across voices with a history
  buffer so skipped filters can be warmed up.
- **Saturation**: 1025-point `tanh` table with linear interpolation.
- **Distortion**: 7 types per voice — Diode, Clip, SAT, BFZ, PDIST, Fold,
  Crush.
- **Pot curves**: 9W9's exponential mappings for tune, decay, drive, pitch.

### The eleven voices

| Index | Enum | GM note | Synthesis |
|-------|------|---------|-----------|
| 0 | `DR_BD` | 36 (35) | Triangle VCO with a downward pitch sweep (base ~49 Hz) → back-to-back diode rounding → 20 Hz DC block → distortion → amp envelope. A short noise "beater click" (LP ~2.5 kHz, 3 ms env) is added. |
| 1 | `DR_SD` | 38 (40) | Two detuned triangles (~205/325 Hz, ratio ~1.585) with pitch sweep and diode shaping, plus a noise path: white noise → HP ~1 kHz → LP ~6.5 kHz with a "snappy" envelope (24 ms hold, then decay). Mixed and distorted. |
| 2 | `DR_LT` | 41 (43) | Three VCOs at f, 1.5f and 2.75f, each with its own envelope (body long; upper partials ~110/70 ms), plus a bandpassed noise "stick" transient; pitch sweep; DC block; distortion. |
| 3 | `DR_MT` | 45 (47) | Same tom model, different tune/decay defaults. |
| 4 | `DR_HT` | 50 (48) | Same tom model, different tune/decay defaults. |
| 5 | `DR_RS` | 37 | Impulse + noise excitation into two high-Q bandpasses (~210 Hz and ~480 Hz), scaled, distorted, highpassed. |
| 6 | `DR_CP` | 39 | Bandpassed noise (~950 Hz) gated by four short burst envelopes spaced ~12 ms apart, followed by a longer tail; distorted. |
| 7 | `DR_CH` | 42 (44) | mu-law sample (`hh.wav`), pitch-shifted and decay-enveloped. Chokes the open hat. |
| 8 | `DR_OH` | 46 | Same `hh.wav` buffer, longer decay. Choked by the closed hat (3 ms fade). |
| 9 | `DR_CR` | 49 (57) | mu-law sample (`crash.wav`), pitch-shifted and decay-enveloped. |
| 10 | `DR_RD` | 51 (59) | mu-law sample (`ride.wav`), pitch-shifted and decay-enveloped. |

Per voice the 909 also has level, tune, decay, drive, distortion type, pan and
reverb/delay sends. The kit has accent and velocity depth. `drum909_param()`
exposes each voice's descriptors (label, range, default, enum names), which the
preenfm3 editor can reuse directly.

## Integration plan for preenfm3

### Decisions

| Topic | Decision |
|-------|----------|
| Voice model | One preenfm3 **carrier voice** carries the whole kit (`getMaxVoices()` = 1, so every GM note reuses that carrier); the 909 handles its own 11 one-shots internally. |
| Note map | Fixed **GM** drum map (table above). |
| RAM | One `drum909_t` per timbre, all 6 timbres. |
| Samples | Include the sampled hats, ride and crash (~110 KB flash). |

### Sound engine

`Drum909Engine : SynthEngine`, one static instance per timbre in
`SynthEngineFactory`:

- State: one `drum909_t` per timbre — a static `drum909Kits_[6]` array in
  `.ram_d1`, referenced by `struct drum909* kit_`; no per-voice state array.
- `getMaxVoices()` returns 1; the mixer "Max voices" for a 909 timbre is
  therefore 1, and engine changes reset/clamp it automatically.
- `noteOn(note, velocity)`:
  - map the GM note to a drum index (unknown notes ignored);
  - `int v = timbre_->allocateVoice(note); if (v == -1) return;`
    (`Drum909Engine` is a friend of `Timbre`);
  - `drum909_trigger(kit_, drum, velocity / 127.0f)`;
  - every later note reuses the same carrier; `bindVoice` has stored it.
- `noteOff`: no-op — every voice is a one-shot and decays on its own.
- `voicesNextBlock()`:
  - render the whole kit at 44.1 kHz in 32-sample chunks into the per-engine
    ring (see Sample rate);
  - resample L/R to `BLOCK_SIZE` frames at 47916 with the fractional phase;
  - interleave L/R into the carrier voice's `getSampleBlock()`;
  - `carrier->fxAfterBlock(0.0f, 0.0f, 0.0f)` so the timbre FX1 applies;
  - keep `carrier->playing_ = true` while the engine owns the carrier;
    `voicesNextBlock()` returns 1 while `drum909_active()`, 0 when silent.
- Why one voice is enough: the 909 already mixes its 11 voices internally and
  `Timbre::voicesToTimbre()` sums the active voice blocks. Per-drum pan is
  handled inside the 909.
- The carrier can be stolen by another timbre when the global pool is full;
  see the steal policy below.
- v1 ignores the 909's own reverb/delay sends (zero them, pass `nullptr`) and
  uses preenfm3's FX1/FX2 on the carrier/timbre.

### Implementation sketch

Phases 0–5 are implemented; this sketch matches the code in the tree.

`Drum909Engine` is a thin adapter around the vendored `drum909_t`:

- Members:
  - `Timbre* timbre_`, `SynthState* synthState_`, `int timbreNumber_`;
  - `struct drum909* kit_` (points into the static `.ram_d1` array);
  - `Drum909Params params_` (the editor/storage view);
  - `Voice* carrier_` (set by `bindVoice`).
- `getMaxVoices()` returns 1; `supportsStepSequencer()` false;
  `reusesSameNoteVoice()` false; `supportsDeferredSteal()` false. The default
  `PLAY_MODE_POLY` is fine.
- `init()`: bind `kit_` to `drum909Kits_[timbreNumber_]`, `drum909_init()`,
  apply `params_`, reset the resampler, clear `carrier_`.
- `bindVoice(Voice* voice)`: `carrier_ = voice; voice->bindTimbre(timbre_);
  voice->playing_ = true; voice->released_ = false;` (`Voice` friend). On a
  re-claim (`carrier_` was non-null), re-init the kit and reset the resampler.
- `noteOn(note, velocity)`: map the GM note to a `DR_*` index;
  `int v = timbre_->allocateVoice(note); if (v == -1) return;`
  call `drum909_trigger(kit_, drum, velocity / 127.0f)` directly.
- `noteOff()`: no-op (one-shots decay on their own). `noteOffVoice()` /
  `noteOffVoiceQuick()`: no-ops. `killVoice()`: clear `carrier_`, re-init the
  kit, reset the resampler.
- `prepareBlock()`, `glide()`, `gateFx()`: no-ops.
- `voicesNextBlock()`:
  - render the kit at 44.1 kHz in 32-sample chunks into the per-engine ring
    (see Sample rate);
  - resample to `BLOCK_SIZE` frames at 47916 with the fractional phase;
  - interleave into `carrier_->getSampleBlock()` (`L, R, L, R, ...`);
  - `carrier_->fxAfterBlock(0.0f, 0.0f, 0.0f)`;
  - return 1 while `drum909_active()` was or is true, else 0.
  When inactive, `carrier_->emptyBuffer()` so the summed timbre block is silent.
- `afterNewParamsLoad()`: `applyParams()` — every pot with `drum909_set()`, then
  `drum909_pan_settle()`; `engineParamChanged()` calls `drum909_set()` directly
  after clamping.
- Storage methods mirror BYOS (see below).
- `EditorDrum909` is a separate `EditorEngine`; see the editor section.

### Carrier voice: current-code limits and hooks

The existing `Timbre`/`Voice` code has several constraints for the one-carrier
design:

- `Timbre::voicesNextBlock()` returns 0 immediately when `numberOfVoices_ == 0`
  (`Timbre.cpp:806`). The carrier must be counted in `numberOfVoices_` before
  the engine's `voicesNextBlock()` is called.
- `Timbre::voicesToTimbre()` sums the blocks of all counted voices
  (`Timbre.cpp:814`) and does not check `Voice::isPlaying()`. The engine only
  has to fill the carrier's `getSampleBlock()`; it does not have to set a
  per-voice level.
- `Voice::getSampleBlock()`, `fxAfterBlock()`, `emptyBuffer()`, `isPlaying()`,
  `getIndex()`, `slot()` and `getCurrentTimbre()` are public.
  `Voice::playing_` and `released_` are private. `Voice` friends `Timbre`,
  `Preenfm3Engine`, `Dx7SynthEngine` and `ByosEngine`; add
  `friend class Drum909Engine;` so 9W9 can keep `playing_ = true` and
  `released_ = false`. Keeping `playing_` true avoids `findFree()` (idle) and
  `findOldestReleased()`, but does not protect against `findOldestPlaying()`.
- Chosen carrier claim: `Drum909Engine` is a friend of `Timbre` and calls
  `allocateVoice(note)`. `ensureActiveVoices()` stays private and remains used
  only by PFM3 unison. `allocateVoice()` is the same path used by DX7/BYOS and
  can reclaim a stolen carrier.
- `Timbre::adoptVoiceFromPool()` is public but not used here; it needs a
  `Voice*` and pool index.
- `Timbre::setVoiceNumber()` is public but only binds an already-chosen voice;
  it does not claim the voice pool and is not a safe substitute.
- `Timbre::getNumberOfVoices()`, `getMaxVoices()` and the new
  `getEngineMaxVoices()` are public and useful for diagnostics.
- `SynthEngine::bindVoice()` is called by `Timbre` whenever a voice is
  claimed; `Drum909Engine` can store the carrier there.
- `SynthEngine::voicesNextBlock()` must return 1 while the kit is audible and
  0 when silent. `Timbre::voicesNextBlock()` returns that value to `Synth`,
  which accumulates `numberOfPlayingVoices_`.
- `SynthEngine::prepareBlock()`, `glide()` and `gateFx()` are called from
  `Timbre::prepareMatrixForNewBlock()`, `Timbre::glide()` and
  `Timbre::gateFx()`; they can be empty.
- `Voice::fxAfterBlock()` is public and is the intended way to run the
  carrier through FX1; `Timbre::gateFx()` can stay empty.
- The new mixer plumbing already supports a 1-voice engine:
  `SynthEngine::getMaxVoices()` defaults to 20 and can be overridden to 1;
  `Timbre::getEngineMaxVoices()`, the private
  `Timbre::clampVoicesToEngineMax()`, and `Synth::newMixerValue()` /
  `Synth::afterNewMixerLoad()` reset or clamp the mixer `numberOfVoices` to
  the engine maximum.

#### Carrier steal policy

No voice lock is added in v1. If another timbre steals the carrier,
`Timbre::reuseVoice()` calls `oldTimbre->removeActiveVoice()`; 9W9's
`numberOfVoices_` becomes 0. `Timbre::voicesNextBlock()` then returns 0
without calling the 9W9 engine, so 9W9 cannot write into a voice now owned by
another timbre. The next note calls `allocateVoice()` again, and `bindVoice()`
updates `carrier_`.

`playing_ = true` and `released_ = false` are still required: `findFree()`
returns owned-but-not-playing voices as idle, and `findOldestReleased()` picks
released voices. They do not protect against `findOldestPlaying()`, which
selects playing, non-released voices by smallest `index_`. A hard lock would
require a core `VoicePool`/`Voice` change; that is out of scope for v1.

### Concurrency

MIDI is decoded in the audio ISR, not the main loop: `preenfm3DecodeMidiIn()`
runs inside `HAL_SAI_TxCpltCallback` / `HAL_SAI_TxHalfCpltCallback`
(`preenfm3.cpp`). Audio also renders in that same ISR (`buildNewSampleBlock`).

The contexts that can reach the engine:

| Context | Priority | Reaches the engine via |
| --- | --- | --- |
| Audio DMA ISR | 3 | MIDI note-on (`preenfm3DecodeMidiIn`), render (`voicesNextBlock`) |
| SysTick ISR | 4 | sequencer note-on (`Sequencer::processActionBetwen` → `noteOnFromSequencer`) |
| Main loop | thread | UI `engineParamChanged`, preset load `afterNewParamsLoad` |

Audio preempts SysTick and the main loop.

**Decision: no queue, no lock.** Call `drum909_trigger()` / `drum909_set()`
directly from `noteOn()` / `engineParamChanged()` / `afterNewParamsLoad()`,
exactly as BYOS, DX7 and PFM3 write their state today. No SPSC ring.

Why this is no worse than the existing engines:

- Aligned 32-bit parameter stores are atomic on Cortex-M7; the audio ISR sees
  either the old or the new value.
- Sequencer note-on already calls `ByosEngine::noteOn()` (allocate + multi-field
  reset) from SysTick with audio preemption possible.
- Worst case is one render block (~0.67 ms) using mixed old/new state. That is
  the same exposure the other engines already have; 9W9 does not need to be
  better.

Guardrails:

- Clamp every value in `engineParamChanged()` before storing it, as the other
  engines do. Never let a parameter select an unbounded array index.
- Confirm in Phase 0 that the vendored `drum909_set()` treats values as plain
  scalars (no context assumption, no unchecked indexing).
- `carrier_` is still set by `bindVoice()`; if it was stolen, check
  `carrier_->getCurrentTimbre() == timbre_` and re-claim on the next note.
- The shared arpeggiator, if enabled, calls `Timbre::engineNoteOn()` from the
  audio context; that is compatible and needs no special handling.

### Parameters, editor, storage

`Drum909Params` follows the BYOS pattern:

- `uint8_t pots[DR_NUM + 1][DR_MAX_PARAMS]` plus pan and kit values.
- `Drum909Engine::engineParamChanged()` clamps/updates `params_` and pushes a
  parameter event; `afterNewParamsLoad()` applies the whole snapshot.

`EditorDrum909` follows `EditorByos`, the smallest working `EditorEngine`:

- Six pages: `BD`, `SD`, `TOM` (LT/MT/HT select), `PERC` (RS/CP),
  `HAT` (CH/OH/CR/RD), `KIT` (accent/velocity).
- `EditorMenu` / `EditorPageButton` / `EditorPageState` with
  `BUTTON_SIMPLE_PARAM`. Use one `EditorPageButton` per main page and a state
  per voice or parameter group when `DR_MAX_PARAMS` does not fit in the six
  encoder slots.
- `EditorSlot.id` is 16-bit and `context` is 8-bit; pack `voice * 16 + param`
  or use `context` for the voice selector.
- Labels, ranges, steps, defaults and enum names come from `drum909_param()`.
  The editor can fill `EditorParamInfo` from it, or use the manual
  `EditorByos` pattern (`displayParamValue`, `encoderTurned`).
- `getCommonPage()` maps page 2 (the third main-page button) to
  `COMMON_PAGE_ARP_FX`; pages 0 and 1 are Parts and Kit. The shared Arp/Fx
  page is provided by the preenFM3, not by 9W9.
- `refreshOscilloBG()` clears the background; `slowTick()` can stay empty.
- `init()` must call `parent->insertEditor(this)`.
- `encoderTurned()` should use
  `synthState_->propagateNewEngineParamValue(...)` like `EditorByos`, so the
  engine and the value display stay in sync.
- `ScreenEditor.cpp` owns one static instance per engine. Add
  `EditorDrum909 drum909EditorInstance;` and call its `init()` from
  `ScreenEditor::init()`. `ScreenEditor::editorForEngine()` then finds it by
  `getEngineType() == SYNTH_ENGINE_DRUM909`.

Storage follows BYOS exactly:

- `getStorageMagic()` returns `PRESET_DRUM909`.
- `getStorageNameOffset(magic)` returns `sizeof(Drum909Params)`.
- Name at `sizeof(Drum909Params)` (13 bytes, padded to 16).
- `TimbreSharedParams` at `sizeof(Drum909Params) + 16`
  (`sizeof(TimbreSharedParams)` is 136).
- `getStorageBlob()` returns
  `sizeof(Drum909Params) + 16 + sizeof(TimbreSharedParams)`.
- `loadStorageBlob()` copies `params_`, then `TimbreSharedParams`, calls
  `timbre_->setSharedParams(shared)`, then applies the parameters.
- The slot is 1024 B with the magic at 1019, so the payload limit is 1019 B.
  `sizeof(Drum909Params)` must stay below
  `1019 - 16 - sizeof(TimbreSharedParams)` = 867 B. The BYOS params are only
  28 B, so the 9W9 parameter block fits comfortably.
- Add `PRESET_DRUM909` to `PersistenceMagic.h` (e.g. `0x44393039`, `"D909"`)
  and a `PresetMagicInfo` row (magic, `SYNTH_ENGINE_DRUM909`, `"909"`).

### Sample rate

- The vendored DSP and samples run at 44.1 kHz (`D9_PHASE_PER_HZ = 2^32 / 44100`,
  `drum909.h`). Leave them unchanged.
- `Drum909Engine::voicesNextBlock()` renders the kit at 44.1 kHz and resamples
  stereo L/R to `BLOCK_SIZE` frames at `PREENFM_FREQUENCY` (47916 Hz).
- Per engine, two 128-sample rings (`ringL_`, `ringR_`) with absolute
  `ringHead_`/`ringTail_` counters and a `phase_` in [0, 1).
- `step = 44100 / 47916 ≈ 0.92036` input samples per output sample. `phase_` is
  the fractional position between `ring[ringTail_]` and `ring[ringTail_ + 1]`.
- Before a block, ensure the ring holds
  `phase_ + (BLOCK_SIZE - 1) * step + 2` samples. While it does not, call
  `drum909_render_st(kit_, tmpL, tmpR, nullptr, nullptr, 32)` and append the 32
  samples to the ring. Zero `tmpL`/`tmpR` first: the 909 accumulates into them.
- For output frame `o`, `p = phase_ + o * step`; linearly interpolate between
  `ring[ringTail_ + (int)p]` and `ring[ringTail_ + (int)p + 1]`.
- After the block, `advance = phase_ + BLOCK_SIZE * step`; `ringTail_ +=
  (int)advance`; `phase_ = advance - (int)advance`. The read head is a few
  samples behind the write head, so the engine adds < 1 block of latency.
- The 909 is asked for **32 samples per call**. 32 input samples cover ~34.8
  output frames, while a block consumes 32, so the ring gains ~2.5 input samples
  per block: in steady state one 32-sample render per output block, and a
  skipped render about every 12 blocks. It never needs two chunks in one block;
  two would only be needed if the 909 returned fewer than ~29.45 samples per
  call. The extra sample beyond 29.45 is the interpolation look-ahead.
- On a re-claim after a steal, the ring and `phase_` are reset.
- The EXP pot tables are in Hz/ms and are rate-independent; the `tanh` table is
  too, so resampling the output is enough.

### Budget

Measured after Phase 5:

- DTCMRAM 78.85 % (103,348 / 131,072 B), RAM_D1 86.04 % (451,084 / 524,288 B),
  RAM_D2 93 %.
- FLASH 40.32 % (792,766 / 1,966,080 B).

9W9:

- RAM: one `drum909_t` per timbre in `.ram_d1`; `sizeof(drum909_t)` ≈ 7.5 KB,
  six kits add 45,192 B, taking RAM_D1 from 77 % to 86.04 % (still below the
  95 % guard). The per-engine 128-sample L/R resampler rings add ~6.1 KB to
  DTCMRAM (74 % -> 78.85 %). Do not put the kits in RAM_D2 (already 93 %).
- Flash: the samples and DSP add 164 KB (628,526 -> 792,766 B, 31.6 % -> 40.3 %).
- Voice pool: `MAX_NUMBER_OF_VOICES` stays 20. 9W9 uses one carrier per
  timbre, so at most six carriers are active across all timbres; no larger
  pool is needed.
- CPU: the 909 is lighter than the 808. Measure a full-kit hit
  (BD + SD + CH + OH + CR), including the 44.1 → 47916 resampler.

### Phased implementation

The phases are ordered so the project builds and the engine is selectable after
each one. Only Phase 4 changes core interfaces/C++ structures.

#### Phase 0 — vendor DSP and generated tables

Add under `third_party/9W9/`:

- `drum909.c`, `drum909.h`, `drum909_dsp.h`, `fastmath.h`, `x0x_param.h`
- `assets/909/{hh,ride,crash}.wav`
- `tools/gen_drum_samples.py`

`third_party/CMakeLists.txt`:

- `add_library(drum909 INTERFACE)` with `${TP}/9W9` on the include path and
  `${TP}/9W9/drum909.c` as an INTERFACE source; link `drum909` into
  `preenfm3_firmware`.

`firmware/CMakeLists.txt`:

- `DRUM909_DIR = ${PROJECT_SOURCE_DIR}/third_party/9W9`.
- `find_package(Python3 COMPONENTS Interpreter REQUIRED)`.
- `add_custom_command(OUTPUT x0x_drum_samples.h x0x_drum_tables.h ...)` writing
  to `${CMAKE_CURRENT_BINARY_DIR}/generated/drum909`, invoking
  `${Python3_EXECUTABLE} ${DRUM909_DIR}/tools/gen_drum_samples.py ${DRUM909_GEN_DIR}/x0x_drum_samples.h`.
  The script takes the samples-header path as its only positional argument and
  writes the tables header next to it; it has no `--fs` option and no resampling.
- `add_custom_target(drum909_generated DEPENDS ...)`;
  `add_dependencies(preenfm3_firmware drum909_generated)`.
- `target_include_directories(preenfm3_firmware PRIVATE ${DRUM909_GEN_DIR})`.
- The project is `LANGUAGES C CXX ASM`, so `drum909.c` compiles as C.
- `drum909.h` / `x0x_param.h` are C headers. Wrap them in `extern "C"` in
  `Drum909Engine.cpp` / `EditorDrum909.cpp` (the upstream headers do not).
- The generator must run before `drum909.c` is compiled. The
  `add_dependencies` on `preenfm3_firmware` covers it; if a build ever races,
  add `OBJECT_DEPENDS` on `${DRUM909_DIR}/drum909.c` in
  `third_party/CMakeLists.txt`.
- Include the generated headers only from `drum909.c`; including them from
  another TU would duplicate the tables.
- The vendored DSP, the generator and `drum909.c` are all 44.1 kHz. Do not
  resample the WAVs; the engine resamples the output (see Sample rate).

Verify: build; both generated headers exist; `drum909.c` compiles with no
warnings. The object is discarded by `--gc-sections` until Phase 1 references
it, so FLASH does not grow yet.

#### Phase 3 — storage

Expected storage work, no core interface change:

- `Drum909Engine::getStorageMagic()` = `PRESET_DRUM909`.
- `getStorageNameOffset(magic)` = `sizeof(Drum909Params)`.
- `getStorageDefaultName()` = `"909"`.
- `getStorageBlob()` / `loadStorageBlob()` copy the BYOS layout:
  - `Drum909Params` at 0;
  - name at `sizeof(Drum909Params)` (13 bytes, padded to 16);
  - `TimbreSharedParams` at `sizeof(Drum909Params) + 16` (136 bytes);
  - `loadStorageBlob()` calls `timbre_->setSharedParams(shared)` and then
    applies the parameters.
- Payload limit is 1019 B; `sizeof(Drum909Params)` must stay below
  `1019 - 16 - 136 = 867 B`.
- `PersistenceMagic.h` (constants and `PresetMagicInfo`) is already done in
  Phase 1.
- No `PatchBank` / `MixerBank` changes: they already dispatch through
  `Timbre::loadStorageBlob()` and the storage-magic table.

Verify: save/load one 909 preset; save/load a mixer containing 909 timbres;
PFM3 ↔ 909 switch on the same timbre; two 909 timbres at once; preset name and
magic correct.

#### Phase 4 — carrier voice (core interface / C++ structure change)

This is the only phase that changes core structures. The chosen path is:

- `Timbre.h`: add `friend class Drum909Engine;`; `ensureActiveVoices()` stays
  private and is still used only by PFM3 unison.
- `Drum909Engine::noteOn()` calls `timbre_->allocateVoice(note)` (same path as
  DX7/BYOS). On the first note it claims one free voice; later notes reuse it.
- `Voice.h`: add `friend class Drum909Engine;` so 9W9 can keep
  `carrier_->playing_ = true` and `carrier_->released_ = false`. These flags
  prevent `findFree()` / `findOldestReleased()` from stealing the carrier, but
  do not prevent `findOldestPlaying()`.
- No voice lock in v1: accept a steal and re-claim on the next note. When the
  carrier is stolen, `Timbre::reuseVoice()` removes it from 9W9
  (`numberOfVoices_` becomes 0); `Timbre::voicesNextBlock()` returns 0 without
  calling the engine; the next note re-claims.

`Drum909Engine` work:

- `bindVoice(Voice* voice)` stores `carrier_`, binds the timbre, and keeps
  `playing_ = true` / `released_ = false`.
- `noteOn()` calls `timbre_->allocateVoice(note)` before triggering;
  returns if `-1`.
- `voicesNextBlock()` returns 1 while active, 0 when silent.
- The carrier is the only voice the engine uses; `Timbre::voicesToTimbre()`
  sums its block.

Verify: the first note claims exactly one voice; later notes reuse it; no
extra voice is allocated; `Timbre::voicesNextBlock()` calls the engine once the
carrier is counted; a stolen carrier goes silent until the next note, then is
re-claimed.

#### Phase 5 — DSP rendering and concurrency

Engine implementation, no core interface change:

- `Drum909Engine` members: `Drum909Params params_`, `Voice* carrier_`, and a
  `struct drum909* kit_` pointing into a static `drum909_t drum909Kits_[6]`
  array placed in `.ram_d1` (one kit per timbre). The pointer keeps `drum909.h`
  and the generated table header out of `Drum909Engine.h`.
- `init()`: bind `kit_` to the timbre's kit, `drum909_init()`, apply `params_`,
  reset the resampler, clear `carrier_`.
- `noteOn()`: map the GM note (36/35 BD, 38/40 SD, 41/43 LT, 45/47 MT, 48/50
  HT, 37 RS, 39 CP, 42/44 CH, 46 OH, 49/57 CR, 51/59 RD; unknown notes
  ignored), allocate the carrier, then `drum909_trigger(kit_, drum,
  velocity / 127)`.
- `noteOff()`: no-op; `noteOffVoice` / `noteOffVoiceQuick`: no-op (one-shots);
  `killVoice`: clear the carrier, re-init the kit and reset the resampler.
- `bindVoice()`: on a re-claim after a steal, re-init the kit and reset the
  resampler.
- `prepareBlock()` / `glide()` / `gateFx()`: no-ops.
- `voicesNextBlock()`: render the kit at 44.1 kHz in 32-sample chunks into the
  per-engine ring, resample to 47916 with the fractional phase (see Sample
  rate), interleave into `carrier_->getSampleBlock()`, call
  `carrier_->fxAfterBlock(0.0f, 0.0f, 0.0f)`, return active ? 1 : 0; when
  inactive, clear the carrier block.
- `applyParams()`: every pot via `drum909_set()`, then `drum909_pan_settle()`
  so a preset load does not pan-sweep. `afterNewParamsLoad()` calls it;
  `engineParamChanged()` calls `drum909_set()` directly after clamping.
- `getMaxVoices() = 1`; the generic mixer reset/clamp already handles it.

Verify: GM notes 36, 38, 42, 46, 45, 47, 50, 39, 37, 49, 51; one-shot decay
and retrigger; CH/OH choke; two 909 timbres; worst-case CPU with a full kit.
